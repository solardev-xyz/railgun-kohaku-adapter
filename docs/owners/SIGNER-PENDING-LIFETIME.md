# Stable-owner pending signer lifetime

This is an explicit behavior fix over 8e41803c7d1efa79c5249f77c36a989208877db9, not a source relocation. The previous rejection/unobservable-closure quarantine did not cover the genuine supervisor case where original task.closed remains pending forever. identity.close() could release the identity owner slot while original signing work and its host loan remained held.

Both private and relay signer admission now latch the stable profile/account owner synchronously before starting work. New identity opening checks this separate latch. Existing identity currency checks do not: the already admitted operation must remain usable. Identity close, vault replacement, cancellation, timeouts and wiping never release this latch. Cleanup waits for the observed original child closure, original admitted requests (and relay observed promises), and original host credential loan settlement before clearing it. An unobservable/rejected closure retains permanent quarantine. A synchronous spawn failure with no returned task can drain and release normally; a returned task whose closure cannot be obtained is quarantined.

Tests use existing controlled fixed job/credential/context seams; they do not execute a utility or derive funded credentials. Six new controls cover both signer domains, same-account close/vault replacement refusal while original closure is pending, unaffected unrelated accounts, live admitted identity, original host settlement after closure, eventual safe reopening, and pending original request after child closure. A detached mutant removing only the pending-owner open gate failed all six new controls; source was restored before validation.

The new SIGNER-LIFETIME transform is inverted before CALLER/PROCESS and existing original provenance, and updates only the changed identity capability pin/test pin. Existing source records and allowlists remain unchanged. First full run found two stale source/test pins, corrected explicitly by the generator; retained log is not reported as a passing run. No public raw-key API, owner activation, native/runtime/profile work or package publication.
