# Repo-only credential conformance harness

The normative [contract](CREDENTIAL-HOST-CONTRACT.md) and [public vectors](../../test/conformance/credential-vectors.json) belong to this repository. The adopting wallet retains the fixed vault primitive. `tools/conformance/credentials.cjs` is test tooling, excluded from package runtime exports and npm files. It never accepts or derives a seed and cannot issue a credential capability.

An adopting test supplies `checkCredentialRow({host,row,createContext})`. `host` must be its actual fixed credential host; `createContext(row,purpose)` must construct a genuine host context and return `{request,assertProfileGuard,close}`. The exact request is `{handle,vaultSession,accountIndex,purpose,signal}`. `assertProfileGuard` is used for the storage-root row and must describe any explicit filesystem seam honestly. The checker compares all four purposes, including equal spending-public/sign bytes, validates an owned 32-byte buffer, holds the original callback promise until explicit settlement and checks the borrowed buffer was wiped. Its deliberately throwing own `then` method distinguishes consumers that use an overridden method rather than observe the original promise.

Run every row separately with the corresponding active fictitious profile and the public mnemonic. Close every genuine context after the host's original work settles. The checker does not prove OS isolation, native worker behavior, signing authorization, complete intermediate seed wiping, or host storage-guard authenticity. Keep the adopting host's negative admission, abort/session/profile changes, hostile promise/species and unknown-exit tests; successful byte vectors are not substitutes for those contracts.

The five package tests are harness controls: a controlled test host succeeds; altered material, omitted wiping and early settlement each refuse. The copied fixture is pinned at SHA-256 `b8a307b09928447bded772da46de8826e597ce013d80e4a51458a1d9946cd1af`. No package runtime uses it.

The separate Freedom conformance candidate runs the exact checker bytes against the real credential host, real `privacy-keys`/hardened primitive and genuine privacy contexts for all six rows (24 loans). Vault/profile leaves and the storage-root guard are explicit public test seams. Its existing negative cases remain unchanged. The full selected host/keystore/primitive suites passed 114 tests, including an unchanged actual-guard test that creates a fresh disposable directory; no existing user profile or wallet was accessed. The initial `npm test` wrapper forwarded the three suite paths but consumed the requested runner/filter flags, so the recorded result is all 114 tests, not a filtered run.

`CREDENTIAL-CONFORMANCE-SOURCES.json` pins the actual Freedom primitive and consumers. The sole literal production importer of `railgun-key-derivation` at that revision is `privacy-keys.js`; `railgun-credential-host.js` calls its fixed keystore factories instead. `railgun-source-identity-host.js` additionally inventories the primitive's bytes for policy identity; it does not import or execute it. The primitive remains host-private and no seed API was added.

The additional `checkStorageRootDrain` case closes the genuine context while the original root callback is pending. Its `close` must also revoke the request signal. It verifies immediate wiping, continued original-promise retention, and successful void settlement after revocation. Context closure must be idempotent. Run it against the actual adopting host; harness controls also reject omitted abort wiping, premature settlement and a host that refuses the completed drain. Keep the negative host cases for changed currency without revocation, one-sided abort, original rejection and non-void results.

Adopter tests must additionally cover a revoked root drain after vault lock, vault replacement and profile change; the generic checker cannot change those host facts. Freedom covers these in its real host tests. A host that passes only byte-vector and generic drain checks has not qualified those cases.
